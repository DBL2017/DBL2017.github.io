记录阿里云OSS静态博客自动更新证书的问题

2026年11月28日
| 问题排查
| 共2630字
| 阅读时长(6分钟)
文章目录

本文记录如何使用 GitHub Actions 自动检查网站证书，并在证书即将到期时通过 Let’s Encrypt 申请新证书，再将其部署到阿里云 OSS。文中也整理了配置密钥、验证流程和排查过程中遇到的权限问题。

整体流程

自动化流程由 .github/workflows/oss_certificate.yml 启动，证书检查和 OSS 部署逻辑位于 build/oss_certificate.py。

触发工作流
  -> 读取网站当前提供的 HTTPS 证书
  -> 判断证书是否在 30 天内到期
  -> 如果不需要更新：结束
  -> 如果需要更新：使用阿里云 DNS 完成域名验证
  -> 向 Let's Encrypt 申请证书
  -> 检查证书域名并上传到 OSS
  -> 重新连接网站，确认新证书已经生效

工作流在以下情况下启动：

  • main 分支有新提交时；
  • 每天定时执行一次，cron 时间为 UTC 02:23，即北京时间 10:23；
  • 在 GitHub 仓库的 Actions 页面手动运行。

工作流每天都会检查，但只有证书剩余有效期不超过 30 天时才申请和部署证书。Let’s Encrypt 证书通常有效约 90 天。每天检查可以及时发现证书问题，不代表每天都会重新申请证书。

需要配置的 GitHub Secrets

在仓库中打开 Settings → Secrets and variables → Actions → New repository secret，添加以下四个 Repository secrets：

Secret 名称用途提供方
ALIYUN_DNS_ACCESS_KEY_ID让 acme.sh 调用阿里云 DNS APIDNS 专用 RAM 用户
ALIYUN_DNS_ACCESS_KEY_SECRET上述 DNS AccessKey 对应的 SecretDNS 专用 RAM 用户
OSS_ACCESS_KEY_ID让 Python 脚本调用 OSS 部署证书OSS 部署专用 RAM 用户
OSS_ACCESS_KEY_SECRET上述 OSS AccessKey 对应的 SecretOSS 部署专用 RAM 用户

DNS 和 OSS 凭据可以使用不同的 RAM 用户，便于分别控制权限。不要将 AccessKey 或 Secret 写进仓库文件、提交到 Git，或粘贴到公开日志中。若 Secret 曾经泄露，应立即禁用旧密钥并创建新密钥。

创建 DNS 验证用 AccessKey

  1. 在阿里云控制台打开 RAM 访问控制，创建一个专用 RAM 用户，并启用 OpenAPI 调用访问。
  2. 为该用户授权阿里云 DNS（AliDNS）所需权限。
  3. 创建 AccessKey，复制 AccessKey ID 和 AccessKey Secret，分别保存到 ALIYUN_DNS_ACCESS_KEY_ID 和 ALIYUN_DNS_ACCESS_KEY_SECRET。

acme.sh 的 dns_ali 插件通过阿里云 DNS API 查询、添加和清理 ACME 验证用的 TXT 记录。对应的操作包括 alidns:DescribeDomainRecords、alidns:AddDomainRecord 和 alidns:DeleteDomainRecord。权限应尽量限制在必要操作和目标 DNS 区域；如果使用自定义策略限制资源范围，还要确认策略允许插件查询 DNS 托管区域。

域名的 DNS 区域必须存在于该 RAM 用户所属的阿里云账号中，并且域名的权威 NS 记录应指向实际管理该区域的 DNS 服务商。仅在阿里云添加 TXT 记录，而域名实际由其他 DNS 服务商解析，无法完成验证。

配置 OSS 部署权限

OSS_ACCESS_KEY_ID 和 OSS_ACCESS_KEY_SECRET 对应的 RAM 用户需要有权限把证书部署到目标 Bucket 的自定义域名。

实际部署时曾遇到如下错误：

You are forbidden to yundun-cert:CreateSSLCertificate

为该用户添加 AliyunYundunCertFullAccess 后，问题得到解决。该系统策略权限范围较广；若希望采用最小权限，可以进一步根据 OSS 返回的具体错误，改为只授予证书部署所需的操作权限。

工作流中的普通配置

以下值当前直接写在 workflow 中，不需要作为 GitHub Secrets 添加：

配置项当前值说明
OSS_CERT_DOMAINblduan.top需要申请证书并绑定到 OSS 的域名
OSS_ENDPOINThttps://oss-cn-hongkong.aliyuncs.comOSS 服务 Endpoint
OSS_BUCKETbinlin-notes用于托管网站的 Bucket
RENEWAL_THRESHOLD_DAYS30Python 脚本中的续期阈值
cron23 2 * * *每天 UTC 02:23 运行检查

如果要更换域名、Endpoint 或 Bucket，应同步修改 workflow 中对应配置。域名配置出现在检查、签发和部署步骤中，必须保持一致。

证书申请和部署过程

1. 检查线上证书

工作流运行：

python3 build/oss_certificate.py check

脚本使用 OpenSSL 连接目标域名的 HTTPS 443 端口，读取当前网站提供的证书，并比较证书到期时间和续期阈值。结果写入 GitHub Actions 的步骤输出 renewal_required，后续步骤根据该值决定是否运行。

如果证书剩余有效期超过阈值，工作流会跳过安装 SDK、签发证书和部署证书的步骤。

2. 通过 DNS 验证申请证书

需要续期时，工作流安装 oss2，下载 acme.sh，并使用 Let’s Encrypt 生产服务申请 RSA 2048 位证书。acme.sh 使用阿里云 DNS API 添加 _acme-challenge TXT 记录，向 Let’s Encrypt 证明域名所有权。

申请成功后，证书和私钥放在 GitHub Actions runner 的临时目录中，供部署步骤读取。工作流不会把证书私钥提交到仓库。

3. 上传到 OSS 并检查生效情况

部署脚本读取证书和私钥，先用 OpenSSL 检查证书是否适用于目标域名，再查询 Bucket 上该域名现有的证书信息。确认可以安全替换后，脚本调用 OSS API 上传新证书。

上传成功后，脚本会重新读取线上证书进行验证，最多检查 6 次，每次间隔 10 秒。只有发现网站已经提供新证书时才算完成；若 OSS 已接受上传但网站仍未切换，脚本会报错，不会把“上传成功”当成“部署完成”。

如何验证

本地验证

本地运行单元测试：

python3 -m unittest discover -s tests -p 'test_oss_certificate.py' -v

只读检查线上证书：

OSS_CERT_DOMAIN=blduan.top python3 build/oss_certificate.py check

此命令只读取线上证书并输出是否需要续期，不会修改 DNS 或 OSS。需要在本机安装 Python 3 和 OpenSSL。

在 GitHub Actions 手动验证

打开仓库的 Actions → renew OSS certificate → Run workflow。手动运行会执行与定时任务相同的证书检查。如果证书未达到续期阈值，签发和部署步骤会显示为 skipped；这可以验证工作流触发和续期判断，但不会验证完整的签发和部署流程。

为强制触发生产流程而把续期阈值临时调高，会导致工作流向 Let’s Encrypt 申请正式证书，并在成功后部署到当前 OSS Bucket。这不是无副作用的模拟测试。特别是将阈值设为 90 天时，一张有效期约 90 天的新证书可能在每天检查时都满足续期条件。验证后应将阈值恢复为 30 天。

若需要反复测试完整流程，建议准备独立测试域名和测试 Bucket，并使用 Let’s Encrypt staging 服务及单独的测试凭据；不要用生产域名和生产 Bucket 做反复测试。当前 workflow 使用的是 Let’s Encrypt 生产服务，并未配置 staging 模式。

故障排查

阿里云 DNS 添加 TXT 记录失败

日志中出现：

Error adding TXT record to domain: _acme-challenge.blduan.top

查看阿里云 ActionTrail 中同一时间的 DNS API 记录。如果错误为 Forbidden.RAM，例如：

api: DescribeDomainRecords
errorCode: Forbidden.RAM

说明 DNS RAM 用户没有查询 DNS 记录的权限。给该用户添加 alidns:DescribeDomainRecords；完整申请和清理挑战记录还需要 alidns:AddDomainRecord、alidns:DeleteDomainRecord。同时确认 AccessKey ID 与 Secret 配对正确、密钥有效，并确认 DNS 区域由该阿里云账号管理。

日志中的 DomainName: "top" 可能是 acme.sh 从完整域名逐级查找 DNS 托管区域时的探测请求，不表示应该给该用户授予 .top 域名的写权限。排查时检查实际的 DNS 区域和权限策略范围。

OSS 部署时提示 CreateSSLCertificate 被拒绝

日志中出现：

oss2.exceptions.AccessDenied
You are forbidden to yundun-cert:CreateSSLCertificate

说明 OSS 凭据对应的 RAM 用户缺少证书服务权限。确认 OSS_ACCESS_KEY_ID 和 OSS_ACCESS_KEY_SECRET 属于预期的 RAM 用户，并为该用户授予证书部署权限。实际排查中，添加 AliyunYundunCertFullAccess 后解决了该错误。

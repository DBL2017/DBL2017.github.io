记录阿里云OSS静态博客自动更新证书的问题

2026年11月28日
| 问题排查
| 共5762字
| 阅读时长(12分钟)
文章目录

阿里云将个人证书的签名时间从一年缩短到90天，意味着采用OSS部署的静态博客需要每90天登录一次阿里云控制台重新申请新的证书，然后更新OSS绑定域名的证书。

为了解决这个问题，本文记录如何使用 GitHub Actions 自动检查静态博客网站证书，并在证书即将到期时通过 Let’s Encrypt 申请新证书，再将其部署到阿里云 OSS。

整体流程

自动化流程由 .github/workflows/oss_certificate.yml 启动，证书检查和 OSS 部署逻辑位于 build/oss_certificate.py。

触发工作流
  -> 读取网站当前提供的 HTTPS 证书
  -> 判断证书是否在 10 天内到期
  -> 如果不需要更新：结束
  -> 如果需要更新：使用阿里云 DNS 完成域名验证
  -> 向 Let's Encrypt 申请证书
  -> 检查证书域名并上传到 OSS
  -> 重新连接网站，确认新证书已经生效

工作流在以下情况下启动：

  • main 分支有新提交时；
  • 每天定时执行一次，cron 时间为 UTC 18:23，即北京时间 2:23；
  • 在 GitHub 仓库的 Actions 页面手动运行。

工作流每天都会检查，但只有证书剩余有效期不超过 10 天时才申请和部署证书。Let’s Encrypt 证书通常有效约 90 天。每天检查可以及时发现证书问题，不代表每天都会重新申请证书。

需要配置的 GitHub Secrets

在仓库中打开 Settings → Secrets and variables → Actions → New repository secret，添加以下四个 Repository secrets：

Secret 名称用途提供方

ALIYUN_DNS_ACCESS_KEY_SECRET上述 DNS AccessKey 对应的 SecretDNS 专用 RAM 用户的 Access Key Secret
OSS_CERT_DOMAIN生成证书时绑定的域名，供 Python 脚本使用证书对应的域名
OSS_BUCKET证书绑定域名对应 OSS BucketOSS 中绑定静态博客域名的bucket_name
OSS_ENDPOINTOSS Bucket对应的 EndpointOSS bucket对应的Endpoint
OSS_ACCESS_KEY_IDOSS 部署证书时对应的 Access Key ID，用于访问 OSSOSS 部署专用 RAM 用户的Access Key ID
OSS_ACCESS_KEY_SECRET上述 OSS AccessKey 对应的 SecretOSS 部署专用 RAM 用户的Access Key Secret

DNS 和 OSS 凭据可以使用不同的 RAM 用户，便于分别控制权限。不要将 AccessKey 或 Secret 写进仓库文件、提交到 Git，或粘贴到公开日志中。若 Secret 曾经泄露，应立即禁用旧密钥并创建新密钥。

创建 DNS 验证用 AccessKey

  1. 在阿里云控制台打开 RAM 访问控制，创建一个专用 RAM 用户。
  2. 为该用户授权阿里云 DNS（AliDNS）所需权限（AlyunDNSFullAccess）。
  3. 创建 AccessKey，复制 AccessKey ID 和 AccessKey Secret，分别保存到 ALIYUN_DNS_ACCESS_KEY_ID 和 ALIYUN_DNS_ACCESS_KEY_SECRET。

acme.sh 的 dns_ali 插件通过阿里云 DNS API 查询、添加和清理 ACME 验证用的 TXT 记录。

对应的操作包括 alidns:DescribeDomainRecords、alidns:AddDomainRecord 和 alidns:DeleteDomainRecord。针对这3中操作，需要给对应的RAM用户（dns_cert）开通AliyunDNSFullAcess账户权限即可。

域名的 DNS 区域必须存在于该 RAM 用户所属的阿里云账号中，并且域名的权威 NS 记录应指向实际管理该区域的 DNS 服务商。仅在阿里云添加 TXT 记录，而域名实际由其他 DNS 服务商解析，无法完成验证。

配置 OSS 部署权限

  1. 在阿里云控制台打开 RAM 访问控制，创建一个专用 RAM 用户（oss），并创建 AccessKey，复制 AccessKey ID 和 AccessKey Secret，分别保存到 OSS_ACCESS_KEY_ID 和 OSS_ACCESS_KEY_SECRET
  2. 为该用户授权阿里云 OSS 和 证书操作所需权限（AliyunOSSFullAccess和AliyunYundunCertFullAccess）。
  3. 记录保存博客文件的 OSS Bucket 的name和绑定的域名，分别保存为 OSS_BUCKET 和 OSS_CERT_DOMAIN。
  4. 记录访问 OSS Bucket 的 Endpoint，保存为 OSS_ENDPOINT。

证书申请和部署过程

工作流配置文件oss_certificate.yml，该文件是用于Github Actions运行，详细内容见下：

# oss_certificate.yml
name: renew OSS certificate
# 以下任一条件满足时，GitHub Actions 都会启动证书检查：
# - main 分支有新提交；
# - 每天按北京时间 02:23（UTC 18:23）定时执行；
# - 仓库管理员在 Actions 页面手动启动。
on:
  push:
    branches:
      - main
  schedule:
    - cron: "23 18 * * *"
  workflow_dispatch:
# 工作流只需要读取仓库代码，不需要修改仓库内容。
permissions:
  contents: read
# 同一时间只运行一个证书更新任务。若前一个任务尚未结束，
# 后续任务会等待，而不是中途取消前一个任务。
concurrency:
  group: oss-certificate-renewal
  cancel-in-progress: false
jobs:
  renew:
    # 使用 GitHub 提供的 Ubuntu 临时虚拟机执行任务。
    runs-on: ubuntu-latest
    # 防止外部服务异常时任务一直占用运行资源。
    timeout-minutes: 20
    steps:
      # 把当前仓库的文件下载到虚拟机，后续步骤才能运行其中的脚本。
      - name: Checkout
        uses: actions/checkout@v7
      # 连接网站并读取当前正在提供服务的证书，判断是否需要更新。
      # 检查结果会写入 GitHub Actions 的步骤输出，供后续步骤决定是否运行。
      - name: Check currently served certificate
        id: check
        env:
          OSS_CERT_DOMAIN: xxx.top
        run: python3 build/oss_certificate.py check
      # 只有证书即将到期时才安装阿里云 OSS 的 Python SDK，
      # 这个 SDK 用于之后把新证书上传到 OSS。
      - name: Install OSS SDK
        if: steps.check.outputs.renewal_required == 'true'
        run: python3 -m pip install oss2
      # 只有确实需要更新时才申请新证书。
      # acme.sh 使用 Let's Encrypt 签发证书，并通过阿里云 DNS
      # 自动完成域名所有权验证；私钥和证书文件保存在本次任务的临时目录中。
      - name: Issue certificate with Let's Encrypt
        if: steps.check.outputs.renewal_required == 'true'
        env:
          # 这两个值应在仓库 Secrets 中配置，供 DNS 验证使用，
          # 不会直接写入仓库文件。
          Ali_Key: ${{ secrets.ALIYUN_DNS_ACCESS_KEY_ID }}
          Ali_Secret: ${{ secrets.ALIYUN_DNS_ACCESS_KEY_SECRET }}
          OSS_CERT_DOMAIN: ${{ secrets.OSS_CERT_DOMAIN}}
        run: |
          # 在开始申请前确认 DNS 凭据已配置；缺少凭据就明确报错退出。
          test -n "$Ali_Key" || { echo "ALIYUN_DNS_ACCESS_KEY_ID is required" >&2; exit 1; }
          test -n "$Ali_Secret" || { echo "ALIYUN_DNS_ACCESS_KEY_SECRET is required" >&2; exit 1; }
          # 下载 acme.sh，并为它的运行数据和生成的证书创建临时目录。
          git clone --depth 1 https://github.com/acmesh-official/acme.sh.git "$RUNNER_TEMP/acme.sh"
          mkdir -p "$RUNNER_TEMP/acme-home" "$RUNNER_TEMP/oss-certificate"
          # 使用 Let's Encrypt 和阿里云 DNS 验证申请证书，
          # RSA 密钥长度为 2048 位。
          "$RUNNER_TEMP/acme.sh/acme.sh" \
            --home "$RUNNER_TEMP/acme-home" \
            --config-home "$RUNNER_TEMP/acme-home" \
            --issue \
            --server letsencrypt \
            --dns dns_ali \
            --keylength 2048 \
            -d "$OSS_CERT_DOMAIN"
          # 将申请得到的私钥和完整证书链复制到指定文件，
          # 供下一步部署到 OSS。
          "$RUNNER_TEMP/acme.sh/acme.sh" \
            --home "$RUNNER_TEMP/acme-home" \
            --config-home "$RUNNER_TEMP/acme-home" \
            --install-cert \
            -d "$OSS_CERT_DOMAIN" \
            --key-file "$RUNNER_TEMP/oss-certificate/private.key" \
            --fullchain-file "$RUNNER_TEMP/oss-certificate/fullchain.pem"
      # 只有证书已申请成功时才部署。脚本会检查证书域名、确认 OSS
      # 上已有可安全替换的证书，然后上传并检查网站是否已经启用新证书。
      - name: Deploy certificate to OSS
        if: steps.check.outputs.renewal_required == 'true'
        env:
          # OSS 服务地址、存储空间名称和访问凭据。
          # 访问凭据从仓库 Secrets 读取，不能填写到公开代码中。
          OSS_CERT_DOMAIN: ${{ secrets.OSS_CERT_DOMAIN}}
          # 指定 OSS Bucket 所在地域的服务 endpoint。
          OSS_ENDPOINT: ${{ secrets.OSS_ENDPOINT }}
          # 指定网站构建产物要同步到的 Bucket。
          OSS_BUCKET: ${{ secrets.OSS_BUCKET }}
          OSS_ACCESS_KEY_ID: ${{ secrets.OSS_ACCESS_KEY_ID }}
          OSS_ACCESS_KEY_SECRET: ${{ secrets.OSS_ACCESS_KEY_SECRET }}
        run: |
          # 上传前先检查 OSS 凭据，未配置时停止并报告缺少哪项配置。
          test -n "$OSS_ACCESS_KEY_ID" || { echo "OSS_ACCESS_KEY_ID is required" >&2; exit 1; }
          test -n "$OSS_ACCESS_KEY_SECRET" || { echo "OSS_ACCESS_KEY_SECRET is required" >&2; exit 1; }
          # 把证书文件和私钥交给 Python 脚本，由脚本完成校验、
          # 上传以及线上生效检查。
          python3 build/oss_certificate.py install \
            --certificate "$RUNNER_TEMP/oss-certificate/fullchain.pem" \
            --private-key "$RUNNER_TEMP/oss-certificate/private.key"

用于检测和安装OSS 证书的python文件oss_certificate.py见下：

#!/usr/bin/env python3
"""检查网站证书是否即将到期，并在需要时将新证书部署到阿里云 OSS。"""

import argparse
import datetime
import os
import re
import ssl
import subprocess
import sys
import time

# 证书剩余有效期不超过 10 天时，开始更新。
RENEWAL_THRESHOLD_DAYS = 10


def _run_openssl_x509(arguments, certificate):
    """把证书交给 OpenSSL 处理，并返回它输出的文字结果。"""
    result = subprocess.run(
        ["openssl", "x509"] + arguments,
        input=certificate,
        capture_output=True,
        text=True,
        check=True,
    )
    return result.stdout.strip()


def certificate_expiry(certificate):
    """从证书中读取到期时间，并转换成带时区的 UTC 时间。"""
    output = _run_openssl_x509(["-noout", "-enddate"], certificate)
    _, date_text = output.split("=", 1)
    timestamp = ssl.cert_time_to_seconds(date_text)
    return datetime.datetime.fromtimestamp(timestamp, datetime.timezone.utc)


def fetch_live_certificate(domain):
    """连接域名的 HTTPS 443 端口，取回网站当前实际提供的证书。"""
    result = subprocess.run(
        [
            "openssl",
            "s_client",
            "-connect",
            "{}:443".format(domain),
            "-servername",
            domain,
            "-showcerts",
        ],
        input="",
        capture_output=True,
        text=True,
        timeout=20,
        check=False,
    )
    # TLS 连接输出里可能包含其他信息；只提取 PEM 格式的证书正文。
    match = re.search(
        r"-----BEGIN CERTIFICATE-----.*?-----END CERTIFICATE-----",
        result.stdout,
        re.DOTALL,
    )
    if match is None:
        raise RuntimeError(
            "Could not retrieve a TLS certificate from {}:443".format(domain)
        )
    return match.group(0) + "\n"


def renewal_required(expiry, now=None):
    """判断证书是否已到期，或是否会在更新阈值内到期。"""
    if now is None:
        now = datetime.datetime.now(datetime.timezone.utc)
    return expiry <= now + datetime.timedelta(days=RENEWAL_THRESHOLD_DAYS)


def check_certificate(domain):
    """检查线上证书，并把是否需要更新的结果交给工作流。"""
    certificate = fetch_live_certificate(domain)
    expiry = certificate_expiry(certificate)
    due = renewal_required(expiry)
    remaining = expiry - datetime.datetime.now(datetime.timezone.utc)
    print(
        "Certificate for {} expires at {} ({} days remaining); renewal required: {}".format(
            domain, expiry.isoformat(), remaining.days, str(due).lower()
        )
    )
    # GitHub Actions 会提供 GITHUB_OUTPUT 文件，用它把结果传给后续步骤；
    # 本地运行时则直接打印结果，方便查看。
    output_path = os.environ.get("GITHUB_OUTPUT")
    if output_path:
        with open(output_path, "a", encoding="utf-8") as output:
            output.write("renewal_required={}\n".format(str(due).lower()))
    else:
        print("renewal_required={}".format(str(due).lower()))


def _required_env(name):
    """读取必需的环境变量；缺少时立即报错，避免用不完整配置继续操作。"""
    value = os.environ.get(name)
    if not value:
        raise RuntimeError("{} must be set".format(name))
    return value


def install_certificate(domain, certificate_path, private_key_path):
    """验证新证书，将它上传到 OSS，并确认网站已经切换到新证书。"""
    # 读取前一步生成的证书和私钥文件。
    with open(certificate_path, "r", encoding="utf-8") as certificate_file:
        certificate = certificate_file.read()
    with open(private_key_path, "r", encoding="utf-8") as private_key_file:
        private_key = private_key_file.read()

    # 先确认这张证书确实适用于目标域名；不匹配就不继续部署。
    subprocess.run(
        ["openssl", "x509", "-noout", "-checkhost", domain],
        input=certificate,
        capture_output=True,
        text=True,
        check=True,
    )
    # 记下新证书的到期时间，稍后用它判断线上是否已经换成这张证书。
    expected_expiry = certificate_expiry(certificate)

    # oss2 是阿里云 OSS 的 Python SDK，只在部署时需要。
    try:
        import oss2
    except ImportError as error:
        raise RuntimeError(
            "Install the oss2 package before deploying the certificate"
        ) from error

    # 从环境变量读取 OSS 连接信息和密钥，不把敏感凭据写在脚本里。
    endpoint = _required_env("OSS_ENDPOINT")
    bucket_name = _required_env("OSS_BUCKET")
    access_key_id = _required_env("OSS_ACCESS_KEY_ID")
    access_key_secret = _required_env("OSS_ACCESS_KEY_SECRET")

    bucket = oss2.Bucket(
        oss2.Auth(access_key_id, access_key_secret), endpoint, bucket_name
    )
    # 查询这个存储空间的自定义域名绑定信息，找到目标域名对应的配置。
    cname_result = bucket.list_bucket_cname()
    cname = next(
        (item for item in cname_result.cname if item.domain == domain),
        None,
    )
    if cname is None:
        raise RuntimeError(
            "Domain {} is not bound to bucket {}".format(domain, bucket_name)
        )
    certificate_info = cname.certificate
    # OSS 更新证书时需要旧证书 ID，以便明确替换正确的证书。
    previous_cert_id = (
        certificate_info.cert_id if certificate_info is not None else None
    )
    if not previous_cert_id:
        raise RuntimeError(
            "OSS did not return the existing certificate ID for {}; "
            "cannot safely replace its certificate".format(domain)
        )

    # 组装上传请求：提供新证书和私钥，并指定旧证书 ID；
    # 不要求 OSS 删除旧证书，避免意外清理其他证书。
    new_certificate = oss2.models.CertInfo(
        certificate=certificate,
        private_key=private_key,
        previous_cert_id=previous_cert_id,
        force=True,
        delete_certificate=False,
    )
    # 把新证书绑定到该域名。
    bucket.put_bucket_cname(oss2.models.PutBucketCnameRequest(domain, new_certificate))
    print("Uploaded the renewed certificate to OSS for {}".format(domain))

    # OSS 接收请求后，线上切换可能需要一点时间。每隔 10 秒检查一次，
    # 最多检查 6 次；通过比较到期时间确认网站已开始提供新证书。
    for attempt in range(6):
        live_expiry = certificate_expiry(fetch_live_certificate(domain))
        if abs((live_expiry - expected_expiry).total_seconds()) <= 60:
            print("Verified the renewed certificate is served for {}".format(domain))
            return
        if attempt < 5:
            time.sleep(10)

    # 上传成功不代表线上已完成切换；超时仍未看到新证书时明确报错。
    raise RuntimeError(
        "OSS accepted the certificate, but {} is not serving it yet".format(domain)
    )


def main():
    """解析命令行参数，并分派到「检查」或「部署」流程。"""
    parser = argparse.ArgumentParser()
    subparsers = parser.add_subparsers(dest="command", required=True)

    # check 只检查当前线上证书，不会修改任何配置。
    check_parser = subparsers.add_parser("check")
    check_parser.add_argument(
        "--domain", default=os.environ.get("OSS_CERT_DOMAIN", "xxx.top")
    )

    # install 部署新证书；证书和私钥文件路径必须由调用者提供。
    install_parser = subparsers.add_parser("install")
    install_parser.add_argument(
        "--domain", default=os.environ.get("OSS_CERT_DOMAIN", "xxx.top")
    )
    install_parser.add_argument("--certificate", required=True)
    install_parser.add_argument("--private-key", required=True)

    arguments = parser.parse_args()
    # 根据子命令选择对应流程。
    if arguments.command == "check":
        check_certificate(arguments.domain)
    else:
        install_certificate(
            arguments.domain, arguments.certificate, arguments.private_key
        )


if __name__ == "__main__":
    # 统一以易读的错误信息结束失败流程，并返回非零状态，
    # 让 GitHub Actions 将本次工作流标记为失败。
    try:
        main()
    except (OSError, RuntimeError, subprocess.SubprocessError, ValueError) as error:
        print(str(error), file=sys.stderr)
        sys.exit(1)

1. 检查线上证书

工作流运行：

python3 build/oss_certificate.py check

脚本使用 OpenSSL 连接目标域名的 HTTPS 443 端口，读取当前网站提供的证书，并比较证书到期时间和续期阈值。结果写入 GitHub Actions 的步骤输出 renewal_required，后续步骤根据该值决定是否运行。

如果证书剩余有效期超过阈值，工作流会跳过安装 SDK、签发证书和部署证书的步骤。

2. 通过 DNS 验证申请证书

需要续期时，工作流安装 oss2，下载 acme.sh，并使用 Let’s Encrypt 生产服务申请 RSA 2048 位证书。acme.sh 使用阿里云 DNS API 添加 _acme-challenge TXT 记录，向 Let’s Encrypt 证明域名所有权。

申请成功后，证书和私钥放在 GitHub Actions runner 的临时目录中，供部署步骤读取。工作流不会把证书私钥提交到仓库。

3. 上传到 OSS 并检查生效情况

部署脚本读取证书和私钥，先用 OpenSSL 检查证书是否适用于目标域名，再查询 Bucket 上该域名现有的证书信息。确认可以安全替换后，脚本调用 OSS API 上传新证书。

上传成功后，脚本会重新读取线上证书进行验证，最多检查 6 次，每次间隔 10 秒。只有发现网站已经提供新证书时才算完成；若 OSS 已接受上传但网站仍未切换，脚本会报错，不会把“上传成功”当成“部署完成”。

验证方式

本地验证

只读检查线上证书：

$ OSS_CERT_DOMAIN=xxx.top python3 build/oss_certificate.py check
Certificate for xxx.top expires at 2027-02-25T15:34:19+00:00 (89 days remaining); renewal required: false
renewal_required=false

此命令只读取线上证书并输出是否需要续期，不会修改 DNS 或 OSS。需要在本机安装 Python 3 和 OpenSSL。

在 GitHub Actions 手动验证

打开仓库的 Actions → renew OSS certificate → Run workflow。手动运行会执行与定时任务相同的证书检查。如果证书未达到续期阈值，签发和部署步骤会显示为 skipped；这可以验证工作流触发和续期判断，但不会验证完整的签发和部署流程。

为强制触发生产流程而把续期阈值临时调高，会导致工作流向 Let’s Encrypt 申请正式证书，并在成功后部署到当前 OSS Bucket。这不是无副作用的模拟测试。特别是将阈值设为 90 天时，一张有效期约 90 天的新证书可能在每天检查时都满足续期条件。验证后应将阈值恢复为 10 天。

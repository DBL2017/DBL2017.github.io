git使用技巧

2024年12月30日
| 工具使用
| 共2177字
| 阅读时长(5分钟)
文章目录

本文系统整理了 Git 的常用补丁、清理、日志和暂存操作，并补充了针对合并冲突与 Fork 仓库同步场景的实战流程。

在补丁部分，文档说明了如何使用 git format-patch 按提交范围或指定目录生成补丁、使用 git apply 检查和应用补丁、使用 git am 保留提交信息，并给出了冲突解决的处理方法。

在工作区清理部分，文档区分了普通未跟踪文件、忽略文件和嵌套仓库的清理方式，强调执行前应先用 -n 参数预览，以避免误删重要内容。

最后，文档针对下游 Fork 仓库与上游仓库发生冲突或 Pull Request 冲突的情况，给出了添加远程源、切换分支、执行 rebase、解决冲突、继续变基和谨慎强制推送的完整步骤，并说明了 –force-with-lease 能在覆盖远端分支前检查提交是否被他人更新。

config

  1. 查看行尾符（LF/CRLF）：git config --global --get core.autocrlf
  2. 设置行尾符：git config --global core.autocrlf input

行尾符常见配置：

配置提交到仓库检出到本地
trueLFWindows是CRLF，Linux是LF
inputLFLF
false不转换不转换

commit

  1. 修改提交账户名：git commit --amend --author=<email> --no-edit
  2. 在当前提交信息中添加Signed-off-by: xxx：git commit --amend --no-edit -s
  3. 对当前提交进行GPG签名：git commit --amend --no-edit -S

patch

  1. 将某次commit生成patch：git format-patch -1 <commit> -o patches
  2. 将多次commit生成patch：git format-patch <commit-id1>..<commit-id2> -o patches，其中包含<commit-id1>不包含<commit-id2>
  3. 将某次commit中的指定目录打包成patch：git format-patch -1 <commit> -- src/
    1. -1 表示只生成一次 commit 的补丁。
    2. <commit> 可以是提交哈希、分支名、标签名或 HEAD 等引用。
    3. A..B 表示生成 B 可达但 A 不可达的提交；即包含新增到 B 的提交，不包含 A。
    4. -o patches 表示将补丁保存到 patches/ 目录。
    5. -- src/ 表示只包含 src/ 路径的变化；-- 用于分隔提交参数与路径参数。
  4. 生成当前提交相对于上一个提交的补丁：
git format-patch -1 HEAD -o patches

打patch

  1. 检查patch是否可用：git apply --check <xxx.patch>
  2. 批量应用patch（不包含commit）：git apply patches/*.patch，会应用到工作区，丢失commit信息.
  3. git apply --cached会将patch应用到暂存区
  4. 批量打patch（包含commit）：git am patches/*.patch

发生冲突时可以：

# 查看冲突并手动解决
git status

# 冲突解决并暂存后继续
git add <resolved-file>
git am --continue

# 放弃本次 am 操作并恢复到执行 git am 前的状态
git am --abort

如果补丁内容有冲突且希望 Git 尝试使用三路合并：

git am -3 patches/*.patch

rebase

批量提交执行

git rebase -i --exec "<command>"

  1. 对近20个提交重新生成commit sha：git rebase -i --exec "git commit --amend --no-edit" HEAD~20
  2. 对近20个提交进行签名：git rebase -i --exec "git commit --amend --no-edit -S" HEAD~20
  3. 对近20个提交修改Author：git rebase -i --exec "git commit --amend --no-edit --author=<email>" HEAD~20

clean

删除所有未跟踪的文件和目录

先预览将要删除的文件和目录：git clean -nfd

然后执行删除操作：git clean -fd

常用参数：

参数作用
-n只预览，不实际删除
-f强制删除未跟踪文件
-d删除未跟踪目录
-x同时删除被 .gitignore 忽略的文件
-X只删除被 .gitignore 忽略的文件
-i交互式选择删除内容

执行删除前，优先使用 -n 预览，避免误删未提交的工作内容：

# 删除未跟踪的文件和目录，但保留被忽略的文件
git clean -nfd
git clean -fd

# 删除未跟踪文件以及被忽略的文件
git clean -nfdx
git clean -fdx

# 只删除被忽略的文件
git clean -nfdX
git clean -fdX

对于嵌套的 Git 仓库或子模块目录，普通 -f 可能不会删除其未跟踪内容。只有确认不再需要时才使用双重强制参数：

git clean -nffdx
git clean -ffdx

log

搜索与查找

在Git中，你可以使用git log命令结合--grep选项来查找提交记录中的特定字符串。

git log --grep="特定字符串"

这个命令会列出所有提交信息中包含“特定字符串”的提交记录。

例如，如果你想查找提交信息中包含“bugfix”的记录，可以使用以下命令：

git log --grep="bugfix"

此外，你还可以结合其他选项来进一步过滤和查找提交记录：

  1. 忽略大小写：git log --grep="bugfix" -i
  2. 按作者过滤：git log --grep="bugfix" --author="John"
  3. 按日期范围过滤：git log --grep="bugfix" --since="2023-01-01" --until="2023-12-31"

--grep 默认区分大小写；使用 -i 后忽略大小写。多个 --grep 默认按“或”匹配，若需要同时满足多个条件，可配合 --all-match：

git log --grep="bugfix" --grep="登录" --all-match

以单行的形式显示提交记录：git log --oneline。

查看日志

以指定格式获取两个提交之间的所有提交：git log --pretty=format:"%h %ad %an | %s" --abbrev=9 --date=short c575344d6..HEAD

stash

如何对特定文件进行暂存

git stash push -- <filename or pathname>

例如：

git stash push -- src/main.c
git stash push -- src include

使用 -- 可以明确区分 stash 选项和路径，避免文件名与选项冲突。

给 stash 添加说明：

git stash push -m "暂存登录功能修改" -- src/login

常见问题

下游仓库同步上游提交时冲突或者下游仓库创建Pull Request冲突

这种情况下下游仓库一般都是上游仓库的fork，通常需要先把上游目标分支的最新改动合入到下游仓库的功能分支，解决冲突之后再推送。

具体操作步骤如下：

# 查看下游仓库都有哪些源
git remote -v
git remote add upstream <upstream-url>
git switch <下游仓库目标分支>
git rebase upstream <上游仓库目标分支>
# 此时会有冲突，解决冲突
git add <已解决的冲突文件>
git rebase --continue
# 冲突全部解决并完成测试
git push --force-with-lease origin <下游仓库目标分支>

--force-with-lease是一种更谨慎的强制推送，它再覆盖远端分支前，会先确认远端分支仍指向上次获取是看到的提交。如果中间有别人又推送了新提交，当前强制推送会被拒绝，避免误覆盖对方的提交。

取消正在跟踪的文件

如果一个文件正在被跟踪，并且已经提交到远程仓库，当前想要取消跟踪该文件，但是本地又要保留，应该怎么处理？

# 从.git中移除文件索引
git rm --cached <filepath>
# 将该文件添加到.gitignore
echo "<filepath>" >> .gitignore
# 添加并提交
git add .gitignore
git commit -m "fix: stop tracking <filepath>"

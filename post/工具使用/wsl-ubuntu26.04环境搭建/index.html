WSL-Ubuntu26.04环境搭建

2026年11月14日
| 工具使用
| 共2386字

文章目录

本文是一份在 Windows 系统上通过 WSL 2 搭建 Ubuntu 26.04 开发环境的完整操作指南，涵盖 Windows 端 WSL 命令、Ubuntu 26.04 安装导入导出、宿主机文件互访，以及软件源、终端语言、Node.js（NVM）、Copilot、Docker、pyenv Python 3.12 等环境配置与验证方法。

WSL的使用方法

Windows端的WSL命令

以下命令在 Windows PowerShell 或命令提示符中运行：

命令作用
wsl --status查看 WSL 配置和默认发行版信息。
wsl --list --online查看可在线安装的 Linux 发行版。
wsl --list --verbose查看已安装发行版及其运行状态和 WSL 版本；Stopped 表示当前未运行，不代表安装失败。
wsl --set-default-version 2将新安装发行版的默认版本设为 WSL 2。
wsl --set-default Ubuntu-26.04将 Ubuntu-26.04 设为运行 wsl 时默认启动的发行版。
wsl启动默认发行版。
wsl --distribution Ubuntu-26.04启动指定发行版；也可简写为 wsl -d Ubuntu-26.04。
wsl --terminate Ubuntu-26.04关闭指定发行版。
wsl --shutdown关闭所有正在运行的 WSL 发行版及 WSL 2 虚拟机。
wsl --update更新 WSL。
wsl --help查看 WSL 命令帮助。

进入 Ubuntu 后，可用以下 Linux 命令查看和切换目录，或退出发行版：

WSL 2 使用 Windows 虚拟化平台。较新的 VMware Workstation 通常可与 WSL 2 共存；旧版 VMware 可能受影响，建议更新 VMware。具体表现取决于 VMware 版本和虚拟化配置。

WSL 2 导入导出Ubuntu文件系统

可以用 WSL 导出/导入迁移整个 Ubuntu 文件系统。旧电脑和新电脑都在 Windows PowerShell 中操作。

旧电脑：导出发行版

wsl --list --verbose
wsl --shutdown
wsl --export Ubuntu-26.04 E:\Ubuntu-26.04.tar

把 E:\Ubuntu-26.04.tar 复制到新电脑。发行版名称请以 wsl --list --verbose 显示的实际名称为准。

新电脑：导入为 WSL 2

先确保 WSL 已安装并更新，然后运行：

wsl --update
wsl --import Ubuntu-26.04 D:\WSL\Ubuntu-26.04 E:\Ubuntu-26.04.tar --version 2

第一个路径是安装位置，第二个路径是复制过来的归档文件。导入后启动：

wsl -d Ubuntu-26.04

导入的发行版通常会默认以 root 登录。要恢复原来的默认用户，先找出原用户名（通常在 /home 下），再编辑 /etc/wsl.conf，保留文件中其他已有设置，并加入：

[user]
default=你的用户名

然后在 PowerShell 中重启该发行版：

wsl --terminate Ubuntu-26.04
wsl -d Ubuntu-26.04

确认文件、应用和默认用户都正常后，再考虑删除旧电脑上的发行版或备份文件。注意：wsl --export 迁移的是 Linux 文件系统，不会迁移 Windows 侧的 WSL 设置、Windows 应用或另存于发行版之外的数据。

Ubuntu26.04的安装

在管理员身份运行的 PowerShell 或命令提示符中执行：

wsl --list --online
mkdir D:\APP\WSL\Ubuntu26.04
wsl --set-default-version 2
wsl --install --distribution Ubuntu-26.04 --location "D:\APP\WSL\Ubuntu26.04"

按提示重启电脑。首次启动 Ubuntu：

wsl -d Ubuntu-26.04

首次启动时按提示创建 Linux 用户名和密码。输入密码时终端不会显示字符，这是正常的。

和宿主机互相访问文件系统

Windows 的 D 盘在 WSL 中对应 /mnt/d/。例如：

cd /mnt/d/blduan/Desktop

从 Windows 文件资源管理器访问 WSL 文件，可输入：

\\wsl.localhost\Ubuntu-26.04\home\blduan

Ubuntu26.04的环境设置

软件源设置

以下示例将 Ubuntu 软件源改为清华镜像。先备份配置：

sudo cp /etc/apt/sources.list.d/ubuntu.sources \
  /etc/apt/sources.list.d/ubuntu.sources.bak
sudo nano /etc/apt/sources.list.d/ubuntu.sources

将文件中 URIs: 后的官方地址（通常为 archive.ubuntu.com 和 security.ubuntu.com）改为：

https://mirrors.tuna.tsinghua.edu.cn/ubuntu/

保留原有的 Suites、Components、Signed-By 等配置。保存后更新软件包索引：

sudo apt update

如果更新失败，可恢复备份：

sudo cp /etc/apt/sources.list.d/ubuntu.sources.bak \
  /etc/apt/sources.list.d/ubuntu.sources
sudo apt update

若找不到 ubuntu.sources，先运行 ls /etc/apt/sources.list.d/ 查看实际配置文件名。

终端语言设置

要让命令输出为英文，同时保持中文文件名可正常显示，使用英文 UTF-8 locale：

sudo apt update
sudo apt install -y locales
sudo locale-gen en_US.UTF-8
sudo update-locale LANG=en_US.UTF-8

退出 WSL 后，在 Windows PowerShell 中重启发行版：

wsl --terminate Ubuntu-26.04
wsl -d Ubuntu-26.04

查看当前语言设置：

locale

如果 LC_ALL 被单独设置为其他语言，它会覆盖 LANG。确认没有不需要的 LC_ALL 设置。使用 UTF-8 locale 不会损坏中文文件名；如果终端仍不能正确显示中文，使用支持 UTF-8 的终端（如 Windows Terminal）。

安装配置 Node.js 和 npm

推荐使用 NVM 管理 Node.js。npm 会随 Node.js 一起安装；不要再用 sudo apt install nodejs 混装。

在 Ubuntu 中运行：

sudo apt update
sudo apt install -y curl ca-certificates

if ! command -v nvm >/dev/null 2>&1; then
  curl -fsSL https://raw.githubusercontent.com/nvm-sh/nvm/v0.40.3/install.sh | bash
fi

export NVM_DIR="$HOME/.nvm"
[ -s "$NVM_DIR/nvm.sh" ] && . "$NVM_DIR/nvm.sh"

nvm install --lts
nvm alias default 'lts/*'

验证安装：

which node
which npm
node -v
npm -v

which node 和 which npm 应指向 /home/blduan/.nvm/versions/node/.../bin/。WSL 默认会把 Windows 的 PATH 加入 Linux PATH，因此务必检查，避免误调用 Windows 上的 Node.js/npm。若路径仍指向 Windows，确认 NVM 已加载；必要时关闭并重新打开 Ubuntu。

npm 缓存和全局包目录

建议把缓存放在 WSL Linux 文件系统中：

mkdir -p "$HOME/.cache/npm"
npm config set cache "$HOME/.cache/npm" --location=user
npm config get cache

使用 NVM 时不要设置固定的 npm prefix。NVM 会为每个 Node.js 版本管理独立的全局包目录：

npm config get prefix
npm root -g

路径应位于 /home/blduan/.nvm/versions/node/... 下。安装全局包直接使用 npm install -g <包名>，不要加 sudo。如果 prefix 仍显示 Windows 路径，先确认 which npm 指向 NVM，再清除用户级覆盖：

npm config delete prefix --location=user

Copilot

这里使用 GitHub Copilot CLI。安装：

npm install -g @github/copilot --include=optional \
  --registry=https://registry.npmjs.org/

运行命令是copilot，如果出错则重启虚拟机。

Docker

以下是在 Ubuntu WSL 内直接安装 Docker Engine 的方式。若使用 Docker Desktop，建议改用其 WSL Integration，不要重复安装 Docker Engine。

添加 Docker 官方软件源并安装：

sudo apt update
sudo apt install -y ca-certificates curl

sudo install -m 0755 -d /etc/apt/keyrings
sudo curl -fsSL https://download.docker.com/linux/ubuntu/gpg \
  -o /etc/apt/keyrings/docker.asc
sudo chmod a+r /etc/apt/keyrings/docker.asc

echo "deb [arch=$(dpkg --print-architecture) signed-by=/etc/apt/keyrings/docker.asc] https://download.docker.com/linux/ubuntu $(. /etc/os-release && echo ${UBUNTU_CODENAME:-$VERSION_CODENAME}) stable" \
  | sudo tee /etc/apt/sources.list.d/docker.list > /dev/null

sudo apt update
sudo apt install -y docker-ce docker-ce-cli containerd.io \
  docker-buildx-plugin docker-compose-plugin

可直接使用 sudo docker ...。若希望省略 sudo，可将用户加入 docker 组；该组权限相当于 root：

sudo usermod -aG docker "$USER"

退出并重新进入 Ubuntu 后生效。

Docker镜像Ubuntu14.04

拉取并启动 Ubuntu 14.04 容器：

sudo docker pull ubuntu:14.04
sudo docker run -it --name ubuntu14 ubuntu:14.04 bash

退出容器后，容器会停止但保留。再次进入：

sudo docker start -ai ubuntu14

Python 3.12

如果 Ubuntu 仓库默认提供 Python 3.14，建议使用 pyenv 安装 Python 3.12，而不要替换系统 Python。这样系统工具仍使用发行版所需的 Python 版本。

安装构建依赖和 pyenv：

sudo apt update
sudo apt install -y build-essential curl git libssl-dev zlib1g-dev \
  libbz2-dev libreadline-dev libsqlite3-dev libncursesw5-dev xz-utils \
  tk-dev libxml2-dev libxmlsec1-dev libffi-dev liblzma-dev

curl -fsSL https://pyenv.run | bash

把以下配置添加到 ~/.bashrc（如果已存在，不要重复添加）：

export PYENV_ROOT="$HOME/.pyenv"
[[ -d "$PYENV_ROOT/bin" ]] && export PATH="$PYENV_ROOT/bin:$PATH"
eval "$(pyenv init - bash)"

重新加载 Bash 配置并查看可用的 3.12 补丁版本：

source ~/.bashrc
pyenv install --list | grep -E '^[[:space:]]*3\.12\.[0-9]+$' | tail -n 5

选择列表中最新的补丁版本，将下面的 3.12.X 替换为实际版本号：

pyenv install 3.12.X
pyenv global 3.12.X
python --version
python3.12 --version

pyenv global 只设置当前用户的默认 Python，不会替换 /usr/bin/python3。若只希望某个项目使用 3.12，在项目目录中运行 pyenv local 3.12.X，而不是 pyenv global。
